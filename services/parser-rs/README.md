# parser-rs

FR3, week 4. Rust rewrite of the parser with output identical to the Python version, benchmarked
against it on the same filings. The live parser since 2026-10-20: the chart's `services.parser.image`
and `services.parser-backfill.image` are `parser-rs`, and setting them to `parser` rolls back to the
Python service. docker-compose still runs the Python one.

The algorithm is the one specified in `services/parser/src/filing_parser/sections.py`, and the
output is identical: same sections, keys, titles, text and character offsets. Rule 1 depends on
how `lxml.html.fromstring` (lxml 6.0, libxml2 2.14) builds its tree, so `src/html.rs` ports the
parts of libxml2's HTML parser that shape it: the tokenizer, implied and auto-closed elements, end
tag priorities, the 256-level depth limit, the 10 MB text and lookup limits, and encoding
detection with the 4000-byte read window it sees. Python quirks are kept too: a document with no
Part or Item heading, or a block followed by text with control characters, is an error in both.
`src/tables.rs` is generated by `scripts/gen_tables.py` from Python's Unicode tables and
libxml2's HTMLparser.c.

Two binaries. `parser` (`src/bin/parser`) is the service, a drop-in for
[services/parser](../parser): it consumes `documents.fetched` as the same consumer group
(`parser-python`, so a swap resumes from the Python service's offsets), commits after each
message, skips and fails on the same inputs, replaces a document's `silver.filing_sections` rows
with its own (`parser = rust`, `parser_version = rust-N`), supports `--reparse-all` (a document it can't split is logged and passed there too), and emits the
same metrics on `METRICS_PORT` and the same JSON log lines. Same env: `DATABASE_URL`,
`KAFKA_BOOTSTRAP_SERVERS`, `METRICS_PORT`, `LOG_LEVEL`, and `PARSER_TOPIC` / `PARSER_GROUP` to
consume another topic as another group (`parser-backfill` reads `documents.backfill`). Kafka
authentication uses the same variables as the Python services' [libs/kafka](../../libs/kafka)
(`KAFKA_SECURITY_PROTOCOL`, `KAFKA_SASL_MECHANISM`, `KAFKA_SASL_USERNAME`, `KAFKA_SASL_PASSWORD`;
`consumer.rs` `client_config`); SCRAM needs librdkafka built with OpenSSL (rdkafka's `ssl`
feature, the system libssl that native-tls already links). Postgres
connections use TLS with libpq's `sslmode` semantics, like the Python services (`src/bin/parser/
tls.rs`, native-tls/OpenSSL): `prefer` by default, and `disable`, `require`, `verify-ca`,
`verify-full` and `sslrootcert` (a file, or `system`) from the URL or `PGSSLMODE` /
`PGSSLROOTCERT`. `services/parser/tests/test_rust_tls.py` checks every mode against libpq on a
TLS-only server (CI). `parser-rs` reads JSON lines on stdin,
`{"id", "path", "form"}` or `{"id", "path", "exhibit_type", "description"}` (`path` may be
gzipped), and prints each document's sections (`--bench`: size and parse time).

Building needs make, a C++ compiler for the bundled librdkafka and the OpenSSL headers. CI builds
it (Rust 1.99.1): the `rust` job runs `cargo fmt --check`, clippy with warnings as errors and
`cargo test`, and the Python job builds the `parser` binary for `services/parser/tests/
test_rust_service.py`, which runs both services' `--reparse-all` on the same documents and compares
the rows and log fields (`TEST_DATABASE_URL`, `PARSER_RS_BIN`). The image (`Dockerfile`) is a
release build on a distroless runtime with both binaries.

## Equivalence and benchmark

```bash
cargo build --release
python scripts/corpus.py /tmp/corpus   # repo fixtures + bronze documents and exhibits (DATABASE_URL)
python scripts/bench.py /tmp/corpus    # diff both parsers' sections, then time them
python scripts/fuzz.py --n 20000       # random malformed HTML through both parsers
```

Run the scripts with the Python parser installed (`pip install -e services/parser`).

Results (2026-10-19, laptop): 256 documents, zero differences; 57,000 generated documents
(`--tokens 60` and `--tokens 2000`), four parses each, zero differences. Inputs: the 3 NVDA fixtures, the
192 documents in `bronze.filing_documents` and their 61 exhibits; MB uncompressed. Parse time
only (no I/O or gunzip), best of 3 runs per document.

| 10-Q | 64 | 149.3 | 33.0 | 292.4 | 46.8 / 238.8 | 5.6 / 26.8 |

Rule 9 (title headings, 2026-11-02, `rust-4` / `python-4`): `TITLES_10K` / `TITLES_10Q` are
copied into `src/sections.rs`, folded with the same `fold_letter` as the Item regex. Checked with
the repo fixtures (NVIDIA plus the Molina, Edison and TriNet 10-Qs that need rule 9), each parsed
as 10-K, 10-Q and 8-K: 27 parses, zero differences; and `fuzz.py`, whose tokens now include item
titles, their punctuation and parenthetical variants and "Part I, Item 2" cross-references (rule 9
decides ~2,500 of each 20,000 documents per form): 20,000 documents (`--tokens 60`) and 3,000
(`--tokens 2000`), four parses each, zero differences.

Rule 10 (clean titles, 2026-11-09, `rust-5` / `python-5`): `section_title` in `src/sections.rs`
mirrors `_title` in sections.py line by line (the lead set is `TITLE_LEAD` plus two ranges, the
wrapped-title words come from the same `TITLES_10K` / `TITLES_10Q` and `title_core`/`fold_title`).
Written without a local build: its unit tests in `tests/sections.rs` copy the Python ones, and CI's
`cargo test`, clippy, fmt and `test_rust_service.py` (both services' rows on the fixtures) checked it.
The corpus and fuzz comparison above was not rerun for rule 10.

Rule 2's decimal item (2026-11-10, `rust-6` / `python-6`): `item_number`'s decimal branch ends before
anything but a decimal digit (`(?!\d)`) instead of at a word boundary, so "Item 7.01Regulation FD
Disclosure" is item 7.01 as in sections.py. Written without a local build (no cargo on the laptop): unit
cases in `heading_patterns` and `tests/sections.rs`
`a_decimal_item_run_into_its_title_keeps_its_number` (a copy of the Python test); CI's `cargo test`,
clippy, fmt and `test_rust_service.py` check it.

Rule 11, tables beside the text (2026-11-15, `rust-7` / `python-7`): `text_content` records each
`table`, `tr`, `thead`, `td`/`th` element's byte range while it walks the tree (`Walk`: the open
tables, their open row and `thead` count, entered and left exactly where the walk enters and leaves
an element), the start tag keeps a cell's attributes to read its `colspan` (`Dom::spans`), and
`land` maps every cell boundary onto the text in one pass per line (a collapsed run's space comes
from the run's first character; stripped and dropped lines move a boundary to the next or previous
kept character), in characters and bytes. `sections::with_tables` keeps each section's rows. The
text is built exactly as before. The service's `db.rs` writes `silver.filing_tables` with the
sections and keeps unchanged section rows (and their `parsed_at`), as db.py does. Written without a
local build: `tests/sections.rs` copies the Python table tests; CI runs `cargo test`, clippy, fmt,
`test_rust_service.py` (both services' section and table rows on the fixtures, and the Rust service
keeping `parsed_at` on an unchanged re-parse) and `scripts/fuzz.py` (3,000 documents of up to 60
tokens and 300 of up to 2,000, whose tokens now include table fragments, colspans and head rows;
sections compared with their tables) against the debug `parser-rs` binary.

Rules 12 and 13, foreign filers (2026-11-17, `rust-8` / `python-8`, migration 095): `HeadingMatch.sub`
marks an item number followed by `.<letter>` (`sub_item`), `sub_item_20f` drops those and lettered
numbers other than 4A and 16A-16K from a 20-F's headings, `split_3d` / `is_3d_heading` split Item 3
at its risk factors line (byte ranges kept beside the sections), and `whole` makes a 6-K's or 40-F's
document (or a 20-F without Item headings) one section. Written without a local build: unit cases in
`heading_patterns`, `tests/sections.rs` `twenty_f_items_and_whole_documents` (a copy of the Python
tests), and `fuzz.py`, which now also parses every document as a 20-F, 6-K and 40-F/A with 20-F
tokens ("Item 3.D", "D. Risk Factors", "Item 5A", "Item 16F").

Rules 14 and 15 (2026-11-28, `rust-9` / `python-9`, migration 166): the start tag keeps the
attributes rule 14 reads (`IX_ATTRIBUTES`, first of each name, a valueless one as "") of
`*:nonfraction`, `*:context` and `*:unit` elements (`NameInfo.ix`, from the name after its last
`:`); `read_header` reads contexts and units on the tree before `drop_hidden`; the walk records each
fact's byte range (`Frame::Fact`) and `printed_facts` lands them as cells are landed;
`parse_document` assigns each fact its section. `contents_items` (rule 15) runs after `body_from` on
10-Qs, over `contents_end`'s contents. The service writes `silver.printed_facts` with the sections;
`parser-rs` prints `facts` beside `sections`, and `bench.py` / `fuzz.py` compare both (fuzz tokens now
include headers, contexts, units, facts and rule 15's contents). Written without a local build
(formatted with rustfmt 1.99.1 only): `tests/sections.rs` copies the Python tests; CI's cargo test,
clippy, fmt, `test_rust_service.py` (both services' printed facts rows on the NVIDIA fixtures) and
fuzz check it.

Known gap: documents declaring a legacy encoding other than UTF-8/16, ISO-8859-x, windows-1252
or ASCII are decoded with encoding_rs, whose Shift_JIS, GB2312 and Mac Roman tables differ from
the libiconv lxml uses. Every stored document is ASCII.
