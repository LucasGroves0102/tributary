# parser-rs

FR3, week 4. Rust rewrite of the parser, benchmarked against the Python version and swapped in behind the same Kafka topic.

The algorithm is the one specified in `services/parser/src/filing_parser/sections.py`, and the
output is identical: same sections, keys, titles, text and character offsets. Rule 1 depends on
how `lxml.html.fromstring` (lxml 6.0, libxml2 2.14) builds its tree, so `src/html.rs` ports the
parts of libxml2's HTML parser that shape it: the tokenizer, implied and auto-closed elements, end
tag priorities, the 256-level depth limit, the 10 MB text and lookup limits, and encoding
detection with the 4000-byte read window it sees. Python quirks are kept too: a document with no
Part or Item heading, or a block followed by text with control characters, is an error in both.
`src/tables.rs` is generated by `scripts/gen_tables.py` from Python's Unicode tables and
libxml2's HTMLparser.c.

Not wired to Kafka yet: `parser-rs` reads JSON lines on stdin, `{"id", "path", "form"}` or
`{"id", "path", "exhibit_type", "description"}` (`path` may be gzipped), and prints each
document's sections (`--bench`: size and parse time).

## Equivalence and benchmark

```bash
cargo build --release
python scripts/corpus.py /tmp/corpus   # repo fixtures + bronze documents and exhibits (DATABASE_URL)
python scripts/bench.py /tmp/corpus    # diff both parsers' sections, then time them
python scripts/fuzz.py --n 20000       # random malformed HTML through both parsers
```

Run the scripts with the Python parser installed (`pip install -e services/parser`).

Results (2026-10-19, laptop): 256 documents, zero differences; 57,000 generated documents
(`--tokens 60` and `--tokens 2000`), four parses each, zero differences. Inputs: the 3 NVDA fixtures, the
192 documents in `bronze.filing_documents` and their 61 exhibits; MB uncompressed. Parse time
only (no I/O or gunzip), best of 3 runs per document.

| inputs | docs | MB | Python MB/s | Rust MB/s | Python median / p95 ms | Rust median / p95 ms |
|---|---|---|---|---|---|---|
| all | 256 | 277.3 | 32.6 | 286.8 | 2.4 / 125.5 | 0.3 / 12.7 |
| 10-K | 32 | 104.5 | 31.9 | 282.5 | 71.2 / 247.4 | 8.2 / 27.9 |
| 10-Q | 64 | 149.3 | 33.0 | 292.4 | 46.8 / 238.8 | 5.6 / 26.8 |
| 8-K | 99 | 4.4 | 31.5 | 229.3 | 1.4 / 2.3 | 0.2 / 0.3 |
| exhibits | 61 | 19.0 | 33.3 | 283.6 | 2.1 / 20.9 | 0.3 / 2.6 |

Known gap: documents declaring a legacy encoding other than UTF-8/16, ISO-8859-x, windows-1252
or ASCII are decoded with encoding_rs, whose Shift_JIS, GB2312 and Mac Roman tables differ from
the libiconv lxml uses. Every stored document is ASCII.
